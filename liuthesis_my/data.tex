\chapter{Data}

This thesis uses two data sources. The first source is LINCS L1000 gene expression data. Another source is the OmniPath interaction database. These two sources give different kinds of information. LINCS shows how cells respond to drug treatment. OmniPath gives known information about how genes and proteins are linked. LINCS provides the drug response data, while OmniPath provides the graph used by the graph based models.

\noindent The data can be grouped into three connected parts. One part is the gene expression matrix, which stores treatment and control profiles. Metadata and compound annotation tables store cell line, dose, time, plate information, and drug target annotations. The last part is the OmniPath interaction network. The sections below explain these parts and how they are linked by shared identifiers.

\noindent Unless otherwise stated, figures from this chapter were created by the author. Figure~\ref{fig:data_level} was created by the author with AI assistance.

\section{CMap LINCS Dataset}
The NIH Common Fund’s Library of Integrated Network based Cellular Signatures (LINCS) provides large datasets for studying how cells respond to chemical and genetic changes. A major part of LINCS is the L1000 assay. This assay directly measures the expression of 978 landmark genes~\cite{l1000_paper}. These genes were chosen because they capture a large part of the change in gene expression across many biological conditions. The L1000 pipeline can also estimate additional genes from the measured landmark genes, which gives a wider gene space of 12,328 genes in total. The data are widely used because they cover many compounds, cell lines, and experimental conditions, together with matched control samples.

\subsection{L1000 Data Processing Flow}
LINCS L1000 data have been released through the GEO archive and later combined resources such as the CMap LINCS 2020 release. In these resources, the data are commonly organized into several processing stages for the same experiments:
\begin{enumerate}
\item \textbf{Stage 1: Raw fluorescence intensities.} These are the direct assay measurements before correction.
\item \textbf{Stage 2: Deconvoluted probe values.} Probe signals are converted to gene expression values.
\item \textbf{Stage 3: Normalized and inferred gene expression.} Data are normalized across samples and batches. Non landmark genes are estimated from the landmark genes.
\item \textbf{Stage 4: Differential expression signatures.} Treatment and control profiles are compared to show drug effects.
\item \textbf{Stage 5: Consensus signatures.} Replicates and conditions are combined into more stable summary signatures.
\end{enumerate}

\noindent This thesis uses the normalized and inferred gene expression matrix from Level 3 (Stage 3). Figure~\ref{fig:data_level} shows the full processing flow. These data provide normalized and inferred gene expression profiles in a common gene space across samples.

\noindent Level 3 is used because this project needs the treated expression profile and the matched control profile as two separate inputs. The response target is constructed later from these two profiles inside the present pipeline. This is also important because the matched control profile is used as a model input and as the source of cell context. Level 4 is less suitable for this design because it already stores the result after treatment and control have been compared. In other words, it is no longer the original treated profile and the original control profile stored side by side in the same simple form. That makes it harder to use the matched control directly as an input to the model. Level 5 is even further from the present task, because it combines repeated measurements into one summary result. That is useful for some analyses, but it removes sample specific variation that is needed here for paired prediction and uncertainty analysis.

\noindent Each Level 3 experiment is represented as a vector of gene expression values in a shared gene space. We denote a profile by $x \in \mathbb{R}^{G}$. Here $G=12{,}328$ for the full gene set and $G=978$ when only landmark genes are used. Profiles are indexed by identifiers such as \texttt{distil\_id}. They are stored in large matrices where rows are profiles and columns are genes in a fixed order. A separate gene information table maps columns to gene identifiers.


\subsection{Treatment and control data}
\noindent LINCS experiments include both compound treatment profiles and matched control profiles. Here the control samples receive the same solvent as the drug treatment, but no active compound. These profiles cover many cell lines, compounds, and experimental conditions. Each profile is stored as a gene expression vector in the shared gene space. The related metadata, such as cell line, compound, dose, and time, are stored in a separate table and linked to profiles through \texttt{distil\_id}. Treatment profiles describe the cell state after drug exposure. Control profiles describe the same type of setting without the drug itself. The difference between treatment and control is the basis of the perturbation response used later in the thesis.

\subsection{Metadata}
\noindent Metadata come from the LINCS signature annotation table that is released with the Level 3 expression data~\cite{l1000_paper}. Each row describes one signature. The table includes compound identity, cell line, experimental conditions, quality control, and batch related variables. These fields give the biological and technical context for the expression matrices. They also link expression profiles to compound annotations. Reliable pairing, filtering, grouping, and evaluation depend on this information. To make these fields easier to read, Table~\ref{tab:lincs_key_fields} lists the main identifiers and quality related variables that appear in this chapter. They belong to four simple groups: sample identifiers, experimental condition fields, technical batch fields, and quality control fields.

\noindent Each signature is linked to a compound identifier \texttt{pert\_id} and a cell line name \texttt{cell\_iname}. Each signature also has a unique signature identifier \texttt{sig\_id}. The field \texttt{distil\_ids} contains one or more expression profile identifiers, \texttt{distil\_id}, that point to the corresponding rows in the Level 3 matrices.

\noindent The metadata also record the experimental condition through fields such as \texttt{pert\_dose}, \texttt{pert\_dose\_unit}, \texttt{pert\_time}, and \texttt{pert\_time\_unit}. In addition, they include technical context variables such as \texttt{bead\_batch}, \texttt{det\_plates}, and \texttt{det\_wells}. These fields are useful because two samples may look different for technical reasons even when their biology is similar. Without this information, treatment and control samples could be matched across different technical conditions.

\noindent Quality control is also described in the metadata~\cite{l1000_paper}. Some signatures are weak or noisy, so the table includes fields such as \texttt{is\_hiq} and \texttt{qc\_pass}. Other summary fields, such as \texttt{tas}, describe how strong and reproducible a signature is. These variables help identify more reliable profiles and remove noisier ones.


\subsection{Drug target}
\noindent Drug related information is collected from the compound annotation table. This table is indexed by \texttt{pert\_id}. It stores compound names in \texttt{cmap\_name}, target annotations in \texttt{target}, and mechanism of action descriptions in \texttt{moa}. In this thesis, it is used to identify which genes are reported as targets of each drug, so that drug specific input signals can be matched to the expression matrix and the OmniPath graph.

\noindent The \texttt{target} field lists reported protein or gene targets for a subset of compounds. One drug may have several targets, so the field can contain more than one gene. During preprocessing, these target names are mapped to the gene identifiers used in the selected expression space. Only targets that align with the expression matrix and the graph can be used by the model. Target information is not available for all compounds in LINCS because many compounds are still not fully characterized.

\subsection{Table association}
\noindent The main tables are linked by shared identifiers. This makes it possible to trace each expression profile back to its experimental context, including cell line, dose, time, batch, and plate information, and to its compound annotation. These links support consistent filtering, grouping, and matched treatment control comparisons.

\noindent Level 3 expression matrices are indexed by \texttt{distil\_id}. The metadata table contains \texttt{distil\_ids}, which stores one or more \texttt{distil\_id} values for each signature. This field links metadata to expression profiles.

\noindent Each signature row in the metadata table also includes a compound identifier \texttt{pert\_id}. The compound annotation table uses the same identifier as its primary key, which links signatures to drug target annotations.

\noindent The metadata further include biological and technical context variables such as \texttt{cell\_iname}, \texttt{bead\_batch}, and \texttt{det\_plates}. These fields support grouping and stratified analysis by biological and technical context.

Both feature types are linked to expression profiles through the compound identifier.

\section{OmniPath Dataset}
\noindent OmniPath is a public database of gene and protein interactions in human cells. It collects control related information from many studies and databases. This thesis uses the regulatory subset of OmniPath. Each row describes a regulator protein, its target gene, and whether the reported effect is activating or inhibiting.

\noindent For each interaction, OmniPath stores fields that describe direction, sign, and evidence. For example, \texttt{is\_directed}, \texttt{is\_stimulation}, and \texttt{is\_inhibition} indicate whether the interaction is directed and whether it is activating or inhibiting. OmniPath also stores evidence related fields such as \texttt{sources}, \texttt{n\_sources}, \texttt{n\_primary\_sources}, and \texttt{n\_references}.

\noindent OmniPath combines interactions from many sources, so different sources may report different labels for the same edge. One source may report stimulation, while another may report inhibition. OmniPath stores both individual labels and combined fields. These fields can be used during graph construction.

\noindent OmniPath also provides evidence counts for each edge, such as \texttt{n\_sources}, \texttt{n\_primary\_sources}, and \texttt{n\_references}. These fields summarize how many databases and publications support an interaction. In this thesis, the combined labels and evidence counts are used to filter edges and keep interactions with stronger support, although the final graph can still contain imperfect edges.

\noindent Genes from the LINCS expression matrix are mapped to nodes in the OmniPath regulon graph. The resulting directed network encodes transcription factor to gene relationships that are supported by published studies. When this network is combined with gene expression data, the model can use both measured responses and known control information. Figure~\ref{fig:overview_of_omnipath} illustrates the table structure used for graph construction.

\section{Data preprocessing}

\noindent The LINCS Level 3 matrices and metadata are converted into the matrices and vectors used by the models. The main steps are:
\begin{enumerate}
\item select one gene set;
\item build matched treatment and control candidates;
\item compute treatment response targets;
\item prepare drug representations for model input.
\end{enumerate}

\subsection{CMap LINCS L1000 preprocessing}

\subsubsection{Gene set selection}
Two gene spaces are supported. In landmark mode, the 978 landmark genes are used in the order given by the landmark gene list. In full gene mode, all 12,328 genes are loaded from the LINCS gene information table and \texttt{pr\_gene\_id} is used as the identifier. In both cases, one fixed gene order is used across control profiles, treatment profiles, response targets, and drug vectors. This keeps all matrices aligned.

\subsubsection{Metadata filtering}
Preprocessing starts from the metadata table, which links each profile to its cell line, compound identifier, perturbation dose, perturbation time, and batch information. Figure~\ref{fig:l1000_filter_flow} summarizes the effect of the main filtering steps. The pipeline keeps two profile types, compound treatments \texttt{trt\_cp} and matched control samples \texttt{ctl\_vehicle}. These control samples receive the same solvent but no active compound. To reduce heterogeneity across experiments, one fixed time point and one fixed dose setting are used. High quality treatment profiles are also retained through the quality flags in the metadata. Optional filtering by cell line is supported through \texttt{siginfo\_beta.txt}.

    \centering
    \includegraphics[width=0.95\linewidth]{figures/l1000_filter_flow.png}

The final step counts treatment profiles that can be paired with at least one matched control sample that receives the same solvent but no active compound under the context matching rules.}
    \label{fig:l1000_filter_flow}

\noindent From the filtered metadata, control profiles are collected and the \texttt{distil\_ids} field is expanded so that each profile has one unique identifier. For each control profile, the cell line, bead batch, and detection plate are recorded. The expression vectors for these identifiers are then loaded from the Level 3 matrix. The loader reads only the requested identifiers and only the selected gene columns.

\noindent The same procedure is applied to treatment profiles. The field \texttt{distil\_ids} is expanded for each treatment record, and the cell line, compound identifier, bead batch, and detection plate are stored for each sample. The expression vectors for these treatment identifiers are then loaded from the Level 3 matrix.

\noindent For each treatment profile, control candidates are selected from the same cell line and the same experimental context. The primary rule matches cell line, bead batch, and detection plate. If no control exists for this exact match, a relaxed rule matches cell line and detection plate. If no suitable control exists, the treatment profile is removed from the candidate set. At this stage, the loader stores each treatment profile together with its candidate controls.

\noindent In the evaluation pipeline, data splitting is applied to treatment profiles before final control matching. After the split, control pools for training and test are separated. Random matching is then applied within each split. In training, one treatment profile can be matched to several randomly sampled controls. If the candidate pool is smaller than the requested number of matches, sampling is done with replacement. In the test set, each treatment profile is matched to one control. The supervised target is later constructed from the treatment expression vector $x_{\mathrm{trt}}$ and the matched control expression vector $x_{\mathrm{ctl}}$.
This construction is intended to reduce the influence of baseline cell state and focus learning on the change caused by drug treatment. When controls are measured in a similar context, the subtraction can also reduce some shared technical noise, such as batch or plate effects, and reduce unwanted variation in the target.

\noindent Several steps are used to reduce the risk of data leakage. The split is created before the final treatment control pairs are sampled, so paired examples derived from the same treatment profile do not appear on both sides of the evaluation. Control pools are then separated for training and test, which prevents the same control profile from being reused in both sets. In the cold drug target setting, test drugs are removed from the training set. In the cold cell setting, test cell lines are removed from the training set. The test set also uses one matched control per treatment profile, which makes the evaluation stricter and easier to read.

\noindent Every training example is linked to a compound identifier and for each drug, we build a target vector over the selected genes. If a gene is an annotated target of the drug, its position in the vector is marked; otherwise it remains zero. Only treatment examples with usable drug target annotations are retained in settings that require target based features. Examples whose \texttt{pert\_id} cannot be linked to an existing \texttt{target} field are removed.

\noindent After preprocessing, the dataset contains matched arrays for control gene expression, drug target vectors, and response targets. Identifiers for cell line, bead batch, detection plate, and profile ids are also retained. These identifiers are later used for evaluation and grouped analysis.

\subsection{OmniPath graph preprocessing}
\noindent The interaction graph is constructed from OmniPath resources that provide directed control or interaction links. The resulting graph is matched to the selected gene space. Each row describes a source gene and a target gene together with sign information when available.

\noindent OmniPath tables are provided in gene symbols. These symbols are mapped to the gene identifiers used by the expression matrices. Edges are kept only when both endpoints can be mapped and both genes are present in the selected gene set. This ensures that graph nodes, expression vectors, and drug target vectors all refer to the same ordered gene list.

\noindent The graph is represented as a directed edge list. When OmniPath provides sign annotations, each edge is assigned a sign value $w\in\{+1,-1\}$ for stimulation or inhibition. If sign information is missing, the edge can be excluded or treated as unknown, depending on the experiment setting.

\noindent An interaction may appear multiple times across sources. Duplicate edges are merged so that each ordered pair $(u,v)$ appears once in the final graph. The resulting graph is stored as \texttt{edge\_index}, a $2\times E$ integer tensor, together with optional edge attributes such as signed weights. This representation is used directly by the graph neural network.

\noindent In the landmark gene setting used in this thesis, the resulting OmniPath graph contains $978$ nodes and $1{,}627$ directed edges after filtering and deduplication. The node set matches the 978 dimensional landmark expression space, so graph outputs align directly with the prediction targets. When the full gene space is used, the constructed graph contains $12{,}328$ nodes and $26{,}166$ directed edges under the same preprocessing settings.

\subsection{Summary}
\noindent After preprocessing, each modelling example contains a matched control expression profile $x_{\mathrm{ctl}}$, a treated expression profile used later to construct the response target together with the matched control, a drug feature vector aligned to the same gene order, and sample related identifiers such as cell line and profile ids. These inputs from each sample are combined with a fixed OmniPath derived interaction graph.

% \noindent Two gene spaces are supported. In landmark mode, the data use 978 genes and the aligned OmniPath graph contains 978 nodes and 1,627 directed edges. In the full gene setting, the data use 12,328 genes and the aligned OmniPath graph contains 12,328 nodes and 26,166 directed edges. In both settings, one gene order is used across control profiles, treatment profiles, response targets, drug feature vectors, and graph nodes.

\noindent Only treatment examples that can be linked to matched controls and usable drug features are retained for modelling in the relevant experiment setting. In practice, this means that the final dataset contains paired treatment control examples for which the response target and model inputs can both be constructed.
