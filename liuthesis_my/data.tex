\chapter{Data}

This thesis uses two main data sources. The first source is LINCS L1000 gene expression data. The second source is the OmniPath interaction database. These two sources give different kinds of information. LINCS shows how cells respond to drug treatment. OmniPath gives prior knowledge about how genes and proteins are linked. Together, they support models that combine measured perturbation responses with biological knowledge.

\noindent The data can be grouped into three connected parts. One part is the gene expression matrix, which stores treatment and control profiles. Another part is the metadata and compound annotation tables, which store cell line, dose, time, plate information, and drug target annotations. The last part is the OmniPath interaction network. The sections below explain these parts and how they are linked by shared identifiers.

\section{CMap LINCS Dataset}
The NIH Common Fund’s Library of Integrated Network based Cellular Signatures, or LINCS, provides large perturbation datasets for studying how cells respond to chemical and genetic interventions. A major part of LINCS is the L1000 assay. This assay directly measures the expression of 978 landmark genes~\cite{l1000_paper}. These genes were chosen because they capture a large part of the variation in gene expression across many biological conditions. The L1000 pipeline can also infer additional genes from the measured landmark genes, which gives a wider gene space of 12,328 genes in total. The data are widely used because they cover many compounds, cell lines, and experimental conditions, together with matched control samples.

\subsection{L1000 Data Processing Flow}
LINCS L1000 data have been released through the GEO archive and later combined resources such as the CMap LINCS 2020 release. Across releases, the data are commonly organized into several data levels. These levels represent different stages of processing for the same experiments:
\begin{enumerate}
\item \textbf{Level 1: Raw fluorescence intensities.} These are the direct assay measurements before correction.
\item \textbf{Level 2: Deconvoluted probe values.} Probe signals are mapped to gene level values.
\item \textbf{Level 3: Normalized and inferred gene expression.} Data are normalized across samples and batches. Non landmark genes are inferred from the landmark genes.
\item \textbf{Level 4: Differential expression signatures.} Treatment and control profiles are compared to show perturbation effects.
\item \textbf{Level 5: Consensus signatures.} Replicates and conditions are combined into more stable signatures.
\end{enumerate}

\noindent This thesis uses Level 3 data. Figure~\ref{fig:data_level} shows the full processing flow. These data provide normalized and inferred gene expression profiles in a common gene space across samples.

\begin{figure}[H]
    \centering

    \caption{LINCS L1000 data processing workflow. The pipeline converts raw fluorescence intensities (Level 1) to deconvoluted probe values (Level 2), normalized and inferred gene expression (Level 3), differential expression signatures (Level 4), and consensus signatures (Level 5).}
    \label{fig:data_level}
\end{figure}

\noindent Each Level 3 experiment is represented as a vector of gene expression values in a shared gene space. We denote a profile by $x \in \mathbb{R}^{G}$. Here $G=12{,}328$ for the full gene set and $G=978$ when only landmark genes are used. Profiles are indexed by identifiers such as \texttt{distil\_id}. They are stored in large matrices where rows are profiles and columns are genes in a fixed order. A separate gene information table maps columns to gene identifiers.


\subsection{Treatment and control data}
LINCS experiments include both compound treatment profiles and vehicle control profiles. These profiles cover many cell lines, compounds, and experimental conditions. Each profile is stored as a gene expression vector in the shared gene space. The related metadata, such as cell line, compound, dose, and time, are stored in a separate table and linked to profiles through \texttt{distil\_id}. Treatment profiles describe the cell state after drug exposure. Control profiles describe the same type of setting without the active drug. The difference between treatment and control is the basis of the perturbation response used later in the thesis.

\subsection{Metadata}
Metadata come from the LINCS signature annotation table that is released with the Level 3 expression data~\cite{l1000_paper}. Each row describes one perturbation signature. The table includes compound identity, cell line, experimental conditions, quality control, and batch related variables. This metadata gives the biological and technical context for the expression matrices. It also provides the keys that link expression profiles to compound annotations. Without it, reliable pairing, filtering, grouping, and evaluation would not be possible.

\paragraph{Identifiers.}
Each signature is linked to a compound identifier \texttt{pert\_id} and a cell line name \texttt{cell\_iname}. Each signature also has a unique signature identifier \texttt{sig\_id}. The field \texttt{distil\_ids} contains one or more expression profile identifiers, \texttt{distil\_id}, that point to the corresponding rows in the Level 3 matrices.

\paragraph{Experimental condition variables.}
The metadata record perturbation dose and time through fields such as \texttt{pert\_dose}, \texttt{pert\_dose\_unit}, \texttt{pert\_time}, and \texttt{pert\_time\_unit}. These variables define the experimental condition for each signature.

\paragraph{Batch and plate context.}
Measurements can change because of small differences in the experiment. The metadata therefore include a bead batch identifier, \texttt{bead\_batch}, and detection plate information, such as \texttt{det\_plates} and \texttt{det\_wells}. These variables are useful because two samples may look different for technical reasons even when their biology is similar. Without this information, treatment and control samples could be matched across different technical conditions.

\paragraph{Quality control.}
Quality control checks whether a measured profile is strong enough and stable enough for later analysis~\cite{l1000_paper}. This is important because some signatures can be weak or noisy. The metadata therefore include quality fields such as \texttt{is\_hiq} and \texttt{qc\_pass}. Other summary fields, such as \texttt{tas}, describe how strong and reproducible a signature is. These variables help identify more reliable profiles and remove noisier ones.


\subsection{Drug target}
Drug related information is collected from the compound annotation table. This table is indexed by \texttt{pert\_id}. It stores compound names, a target field, and mechanism of action text. It links perturbation signatures in LINCS to annotated information about the compounds. In this thesis, it is used to identify which genes are reported as targets of each drug, so that drug specific input signals can be aligned with the expression matrix and the OmniPath graph.

\paragraph{Target annotations}
The \texttt{target} field lists reported protein or gene targets for a subset of compounds. One drug may have several targets, so the field can contain more than one gene. In preprocessing, these target names are mapped to the gene identifiers used in the selected expression space. This step is necessary because the model can only use targets that can be aligned with the expression matrix and the graph. Target information is not available for all compounds in LINCS. This is expected because many compounds are not fully characterized.

\subsection{Table association}
This subsection summarizes how the main tables are linked by shared identifiers. The goal is to make each expression profile traceable to its experimental context and to its compound annotation. This linkage supports reproducible filtering, grouping, and matched treatment control comparisons. Figure~\ref{fig:trt_ctl_target_expr_map} shows these connections.

\paragraph{Profile key}
Level 3 expression matrices are indexed by \texttt{distil\_id}. The metadata table contains \texttt{distil\_ids}, which stores one or more \texttt{distil\_id} values for each signature. This field links metadata to expression profiles.

\paragraph{Compound key}
Each signature row in the metadata table includes a compound identifier \texttt{pert\_id}. The compound annotation table uses the same identifier as its primary key. This field links signatures to drug target annotations.

\paragraph{Context variables for grouping.}
The metadata also include cell context, \texttt{cell\_iname}, and batch or plate variables such as \texttt{bead\_batch} and \texttt{det\_plates}. These fields support grouping and stratified analysis by biological and technical context.

Both feature types are linked to expression profiles through the compound identifier.

\section{OmniPath Dataset}
OmniPath is a public database that collects information about molecular interactions, signaling pathways, and regulatory relationships in human cells. It combines data from many pathway and transcription factor resources into a single interaction table. In this thesis, the transcription factor regulon part of OmniPath is used. Each row describes a regulator, a target gene, and whether the interaction is activating or inhibiting.

\noindent For each interaction, OmniPath stores fields that describe direction, sign, and evidence. For example, \texttt{is\_directed}, \texttt{is\_stimulation}, and \texttt{is\_inhibition} indicate whether the interaction is directed and whether it is activating or inhibiting. OmniPath also stores evidence related fields such as \texttt{sources}, \texttt{n\_sources}, \texttt{n\_primary\_sources}, and \texttt{n\_references}.

\noindent OmniPath integrates interactions from many resources, so different sources may report different annotations for the same edge. One source may report stimulation, while another may report inhibition. OmniPath stores both individual annotations and consensus fields. These fields can be used during graph construction.

\noindent OmniPath also provides evidence counts for each edge, such as \texttt{n\_sources}, \texttt{n\_primary\_sources}, and \texttt{n\_references}. These fields summarize how many databases and publications support an interaction. In this thesis, consensus and evidence counts are used to reduce uncertainty, although the final graph can still contain imperfect edges.

\noindent Genes from the LINCS expression matrix are mapped to nodes in the OmniPath regulon graph. The resulting directed network encodes transcription factor to gene relationships that are supported by published studies. When this network is combined with gene expression data, the model can use both measured responses and prior regulatory information. Figures~\ref{fig:overview_of_omnipath} and~\ref{fig:omnipath_graph_978_full} illustrate the table structure and the final graph after filtering and alignment.

\section{Data preprocessing}

This section explains how the LINCS Level 3 matrices and metadata are converted into the aligned tensors used by the models. The implementation follows the current data loading pipeline in the code. The goal of preprocessing is:
\begin{enumerate}
\item select a consistent gene set;
\item build matched treatment and control candidates;
\item compute treatment response targets;
\item attach drug features that can be used as model inputs.
\end{enumerate}

\subsection{CMap LINCS L1000 preprocessing}

\paragraph{Gene set selection.}
Two gene spaces are supported. In landmark mode, the 978 landmark genes are used and the Entrez gene identifiers are kept in a fixed order from the landmark gene list file. In full gene mode, all 12,328 genes are loaded from the LINCS gene information table and \texttt{pr\_gene\_id} is used as the identifier. In both cases, one fixed gene order is used across control profiles, treatment profiles, response targets, and drug vectors. This keeps all matrices aligned.

\paragraph{Metadata filtering.}
Preprocessing starts from the metadata table, which links each profile to its cell line, compound identifier, perturbation dose, perturbation time, and batch information. Figure~\ref{fig:l1000_filter_flow} summarizes the effect of the main filtering steps. Two profile types are retained. These are compound treatments, \texttt{trt\_cp}, and vehicle controls, \texttt{ctl\_vehicle}. To reduce heterogeneity across experiments, one time point and one dose setting are used. By default, profiles measured at 24 hours and treatments with dose close to 10~\textmu M are kept. High quality treatment profiles are also retained, for example by using \texttt{is\_hiq = 1}. Optional filtering by cell line is supported through \texttt{siginfo\_beta.txt}.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.95\linewidth]{figures/l1000_filter_flow.png}
    \caption{Effect of successive filtering steps on the number of treatment profiles retained for modelling in a single dose and single time point setting. The final step counts treatment profiles that can be paired with at least one matched vehicle control under the context matching rules.}
    \label{fig:l1000_filter_flow}
\end{figure}

\paragraph{Control profile.}
From the filtered metadata, control profiles are collected and the \texttt{distil\_ids} field is expanded so that each profile has one unique identifier. For each control profile, the cell line, bead batch, and detection plate are recorded. The expression vectors for these identifiers are then loaded from the Level 3 matrix. The loader reads only the requested identifiers and only the selected gene columns.

\paragraph{Treatment profile.}
The same procedure is applied to treatment profiles. The field \texttt{distil\_ids} is expanded for each treatment record, and the cell line, compound identifier, bead batch, and detection plate are stored for each sample. The expression vectors for these treatment identifiers are then loaded from the Level 3 matrix.

\paragraph{Matched pairing and target.}
For each treatment profile, control candidates are selected from the same cell line and the same experimental context. The primary rule matches cell line, bead batch, and detection plate. If no control exists for this exact match, a relaxed rule matches cell line and detection plate. If no suitable control exists, the treatment profile is removed from the candidate set. At this stage, the loader stores each treatment profile together with its candidate controls.

\noindent In the current evaluation pipeline, data splitting is applied at the treatment profile level before final control matching. After the split, control pools for training and test are separated. Random matching is then applied within each split. In training, one treatment profile can be matched to several randomly sampled controls. In the main experiments, the default number is 3 controls per training treatment. If the candidate pool contains fewer than 3 controls, sampling is done with replacement. In the test set, each treatment profile is matched to one control. Figure~\ref{fig:l1000_xdeg_stats} shows the distribution of the resulting response values in the landmark gene setting. The supervised target is the treatment response vector
\[
y = x_{\mathrm{trt}} - x_{\mathrm{ctl}},
\]
where $x_{\mathrm{trt}}$ is the treatment expression vector and $x_{\mathrm{ctl}}$ is the matched control expression vector.
This construction removes much of the baseline cell state and focuses learning on the change induced by drug perturbation. When controls are measured in a similar context, the subtraction also removes some shared technical noise.

\noindent Several steps are used to reduce the risk of data leakage. The split is created before the final treatment control pairs are sampled, so paired examples derived from the same treatment profile do not appear on both sides of the evaluation. Control pools are then isolated for training and test, which prevents the same control profile from being reused in both sets. In the cold drug setting, test drugs are removed from the training set. In the cold cell setting, test cell lines are removed from the training set. The test set also uses one matched control per treatment profile, which keeps the evaluation more conservative and easier to interpret.

\paragraph{Drug feature.}
Each training example is linked to a compound identifier. A sparse target annotation vector over the selected gene set is built by mapping annotated target gene symbols to the gene identifiers used in the expression matrix.
\paragraph{Example filtering.}
Only treatment examples with usable drug target annotations are retained in settings that require target based features. Examples whose \texttt{pert\_id} cannot be linked to an existing \texttt{target} field are removed.

\paragraph{Outputs.}
After preprocessing, the dataset contains aligned arrays for control gene expression, drug target vectors, and response targets. Identifiers for cell line, bead batch, detection plate, and profile ids are also retained. These identifiers are later used for evaluation and grouped analysis.

\subsection{OmniPath graph preprocessing}
In this thesis, the prior interaction graph is constructed from OmniPath resources that provide directed regulatory or interaction links. The resulting graph is aligned to the selected gene space. Each row describes a source gene and a target gene together with sign information when available.

\paragraph{Identifier alignment.}
OmniPath tables are provided in gene symbols. These symbols are mapped to the gene identifiers used by the expression matrices. Edges are kept only when both endpoints can be mapped and both genes are present in the selected gene set. This ensures that graph nodes, expression vectors, and drug target vectors all refer to the same ordered gene list.

\paragraph{Direction and sign.}
The graph is represented as a directed edge list. When OmniPath provides sign annotations, each edge is assigned a sign value $w\in\{+1,-1\}$ for stimulation or inhibition. If sign information is missing, the edge can be excluded or treated as unknown, depending on the experiment setting.

\paragraph{Deduplication and outputs.}
An interaction may appear multiple times across sources. Duplicate edges are merged so that each ordered pair $(u,v)$ appears once in the final graph. The resulting graph is stored as \texttt{edge\_index}, a $2\times E$ integer tensor, together with optional edge attributes such as signed weights. This representation is used directly by the graph neural network.

\paragraph{Graph size.}
In the landmark gene setting used in this thesis, the resulting OmniPath graph contains $978$ nodes and $1{,}627$ directed edges after filtering and deduplication. The node set matches the 978 dimensional landmark expression space, so graph outputs align directly with the prediction targets. When the full gene space is used, the constructed graph contains $12{,}328$ nodes and $26{,}166$ directed edges under the same preprocessing settings.

\subsection{Summary}
After preprocessing, each modelling example contains a matched control expression profile $x_{\mathrm{ctl}}$, a treatment response target $y = x_{\mathrm{trt}} - x_{\mathrm{ctl}}$, a drug feature vector aligned to the same gene order, and sample related identifiers such as cell line and profile ids. These sample level inputs are combined with a fixed OmniPath derived interaction graph.

\noindent Two gene spaces are supported. In landmark mode, the data use 978 genes and the aligned OmniPath graph contains 978 nodes and 1,627 directed edges. In the full gene setting, the data use 12,328 genes and the aligned OmniPath graph contains 12,328 nodes and 26,166 directed edges. In both settings, one gene order is used across control profiles, treatment profiles, response targets, drug feature vectors, and graph nodes.

\noindent Only treatment examples that can be linked to matched controls and usable drug features are retained for modelling in the relevant experiment setting. In practice, this means that the final dataset contains paired treatment control examples for which the response target and model inputs can both be constructed.
